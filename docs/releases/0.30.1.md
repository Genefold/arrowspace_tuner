# arrowspace_tuner 0.30.1

## Version alignment

This release targets ArrowSpace `>=0.30.0,<0.31`, tested against `0.30.0`.
The tuner and ArrowSpace share the major/minor compatibility line; tuner patch
revisions may advance independently. No ArrowSpace 0.30.1 release is required.

**This release contains breaking tuner API changes despite the patch increment.**
Version numbers follow ArrowSpace compatibility rather than strict SemVer for
the tuner's API. Do not treat a tuner patch update as necessarily drop-in.

## New: quality-first, smaller graph configurations

The main search optimizes eps and k. An opt-in, explicitly budgeted refinement
phase tests smaller k and higher eps, retaining full-range eps exploration.
Select the smallest evaluated k within an absolute composite-score tolerance.
The raw objective is unchanged; there is no k penalty.

```python
from arrowspace_tuner import tune

graph_params = tune(
    embeddings,
    n_trials=15,
    selection_policy="lowest_k",
    refinement_trials=8,  # additional attempts beyond n_trials
    score_tolerance=0.0,  # exact score ties only
)
```

Equivalent CLI:

```sh
arrowspace-tuner tune corpus.npy --trials 15 \
  --selection-policy lowest_k --refinement-trials 8 \
  --score-tolerance 0 --format json
```

The same settings are accepted by MCP `tune_graph`. Lowest-k selection is among
evaluated configurations, not a guarantee of the global minimum k. Refinement
is skipped if the main winner already has k_low.

## Breaking changes and migration

- **Only eps and k are optimized.** Remove `tau_low`/`tau_high` constructor,
  request, and MCP arguments and `--tau-low`/`--tau-high` CLI options.
- **No tau result.** Remove accesses to best_tau from Python attributes and
  CLI/MCP responses. Reports and MCP build instructions no longer expose it.
  The internal retrieval evaluation uses fixed 0.5; choose your query-time
  settings independently.
- **Persisted studies:** create a new study for legacy tau-optimized runs.
  Incompatible data/settings are rejected before new trials are added.
- **Graph output remains builder-ready:** eps, k, topk, p, sigma. Existing saved
  graph-parameter dictionaries remain loadable.
- **Selected versus raw winner:** public parameters/metrics and saved best
  parameters describe the selected trial. Optuna's study.best_trial retains
  its raw-score meaning; selection metadata explains any difference.

## Reliability and compatibility

- Invalid, failed, and nonfinite evaluations cannot win selection.
- Refinement retains graph validity guards without statistical median pruning.
- Both phases share the fixed evaluation subsample and probe anchors.
- MCP trial caps include main and refinement attempts.
- Reporting and reload agree on the selected configuration.
- No new runtime dependencies. Reporting and MCP remain optional extras.

Release preparation does not publish packages. Publishing the GitHub release
triggers the existing trusted PyPI publishing workflow.
